Executive Summary ¶

This round 2 review covers the same PR after the author addressed four findings from round 1: fetchConfig race deduplication (I1), containerSetState Content-Type (I6), disconnect callback key collision (I8), and setCurrentNamespace callback replacement (S9). The core architecture — refcounted watchResources/unwatchResources with centralized setupResourceWatch — remains solid.

Two agents independently confirmed that the doneHandler ordering bug dismissed in round 1 (I7) is real: when a component unmounts and closes its watcher, the abort error fires ERROR callbacks before the stopped flag is checked, triggering a full backend reconnect on every page navigation. This is the only finding that blocks merge. One new finding surfaced: the Watcher.#loaded latch is not reset when a stopped watcher restarts, so waitForResources rejects permanently after a stop/start cycle.

Watcher.#loaded is a Latch (a Promise with exposed resolve/reject methods) created once at construction (line 552). When the watcher encounters an error, the error handler at line 605 calls this.#loaded.reject(err). A settled Promise ignores subsequent resolve calls, so restarting the watcher via watchResources (which calls start() at line 494) leaves #loaded permanently rejected. Any subsequent waitForResources call rejects immediately, even though the watcher is running and receiving data.

This bug compounds with I1: intentional closes via unwatchResources reject #loaded through the spurious error path. With the I1 fix applied, intentional closes no longer reject #loaded, but genuine backend errors still do — and the latch remains stale until setupResourceWatch recreates the Watcher.

Fix: Reset the latch in start().

+  this.#loaded = Latch();
+  this.#loaded.catch(() => { /* ignore */ });
   this.#watcher.start().catch(err => {
     console.debug(`Watch ${ this.#type } ended:`, err);
     this.#doneFn(err);
     this.#loaded.reject(err);
   });

Design Observations ¶

Concerns

  1. (in-scope) The watch lifecycle has no semantic distinction between intentional close and backend disconnect. ListWatch.stop() and a backend-initiated disconnect both flow through the same error path, producing the cascade behind I1. Introducing an intentionallyClosed flag in ListWatch or splitting doneHandler into separate paths would eliminate this class of bugs. Codex Gemini
  2. (in-scope) View lifecycles directly drive transport teardown. A component unmounting closes the underlying HTTP connection. Keeping informers alive for the process lifetime and using refcounts only to gate store commits would remove the need to reinterpret aborts as disconnects. Codex

Strengths

  1. The refcounted watchResources/unwatchResources API handles overlapping component lifecycles cleanly. When two components watch the same resource, the watcher runs as long as either is active. [All agents]
  2. The fetchConfig deduplication via fetchConfigPromise (new in this round) prevents concurrent reconnection storms without adding complexity. Claude
  3. Lazy fieldSelector/labelSelector evaluation via functions ensures namespace changes propagate to watchers on reconnect without rebuilding them. Claude
  4. The setHeaderOptions middleware approach for overriding Content-Type avoids modifying generated code and composes well with other middleware. Claude

Testing Assessment ¶

  1. No tests for unwatchResources on the last subscriber — this is the path that triggers I1 and runs on every page teardown.
  2. No tests for waitForResources after a stop/start cycle — this is the path affected by I2.
  3. No tests for ensureAppStarted — the create/patch/poll loop with 409 handling is the core new behavior and is untested.
  4. BackendProgress.spec.ts entirely skipped — describe.skip at line 42 disables all meaningful coverage. Acknowledged by the author as intentional (backend progress format not yet defined).

Documentation Assessment ¶

The JSDoc comments on ResourceWatchActionsReturn (lines 330-358) clearly describe the expected lifecycle for each action. No blocking documentation gaps.

Acknowledged Limitations ¶

  1. rddConnection.ts:381-382: Config fetch failures during reconnection are silently retried without user notification. The TODO notes this should emit a diagnostic.
  2. BackendProgress.vue:67-89: The k8s-progress IPC listener is commented out, disabling detailed progress reporting. The author notes the backend has not specified the progress format.
  3. container-engine.ts:91-92: Setting currentNamespace to undefined skips setupResourceWatch, leaving old watchers running with the previous fieldSelector.
