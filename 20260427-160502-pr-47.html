Executive Summary ¶

Round 2 rebases the prior "namespace from app" PR onto a substantially rewritten watch path. The architectural moves are good: namespace tracking moved into rdd-connection (a new addNamespacedResource registry plus a SET_NAMESPACE mutation), rewatchResources action replaces full-setupResourceWatch re-entry on namespace change, Watcher.start() recreates the inner ListWatch and uses Object.is(watcher, this.#watcher) stale-watcher checks, and the rdd module's unused configMaps resource is dropped. Round 1's I2 (rdd asymmetry), I3 (concurrency in setupResourceWatch), and I4 (transient-undefined rebind) are addressed by these moves.

What landed less cleanly: the error handler on the inner ListWatch now calls clearTimeout(this.#restartTimeout) before the stale-watcher check, so a deferred error from a closed watcher cancels a still-pending 429 restart on the live watcher; the callback parameter type widened from a strict ResourceNames<T> union to ResourceNames<T>[number], which evaluates to plain string and silently loses callback-arg type safety; and the round-1 fallback-when-spec.namespace-undefined concern returned in a new shape (the rdd-side if (newNamespace) guard now drops legitimate undefined → 'default' transitions). Several round-1 Suggestions remain unaddressed and resurface here (Images.vue stale kubeNamespace mapping, redundant primitive equality guard, missing JSDoc on kubernetesNamespace).

Structure: 0 critical, 3 important, 10 suggestions, 1 design observation.

Design Observations ¶

Strengths ¶

  • (in-scope) Recreating the inner ListWatch in every Watcher.start() (lines 619-680) and gating callbacks on Object.is(watcher, this.#watcher) is exactly the right shape for repeated rewatches — it avoids the long-standing ListWatch.start() re-use fragility and makes stale events safe to ignore. Codex Claude
  • (in-scope) Promoting path, labelSelector, and fieldSelector to thunks on the Watcher (lines 412, 449-450) lets each start() re-evaluate against current store state, so the rewatch flow works without recreating the wrapping Watcher. Claude
  • (in-scope) Tracking namespaced resources in rdd-connection.namespacedResources (a Record<string, Set<string>>) and dispatching rewatchResources per module on namespace change is cleaner than the prior disconnect-callback indirection, and isolates per-watcher reconnect inside doneFn. Claude
  • (in-scope) The Latch.settled accessor (pkg/rancher-desktop/utils/latch.ts:24-25,90-94) is a minimal addition wired correctly into resolve/reject/reset, and the setupResourceWatch "called more than once" guard that uses it is the right shape. Claude
  • (in-scope) Multi-line regex fix in pkg/rdd-client/watch.ts — switching from /^(.*?)\r?\n(.*?)$/m to /^(.*?)\r?\n(.*)$/s resolves a chunking bug where multiple JSON events in a single buffer read were swallowed because . in non-s mode does not match newlines, so (.*?) after the newline could not capture the remainder. Gemini
  • (in-scope) Dynamic listFn discovery in setupResourceWatch (lines 383-409) — picking listNamespaced<Type> vs list<Type> based on the client shape — removes the per-resource list: boilerplate across container-engine.ts and rdd.ts and centralizes the namespaced/cluster-scoped distinction. Gemini
  • (in-scope) Plugin<RootState> typing across all four modules (round 1's I2-related hygiene) is uniform and removes the per-module Plugin<ModuleState> divergence. Claude

Concerns ¶

  • (in-scope) Periodic-reconnect behavior changed materially with the new watch.ts timeout semantics Claude

Pre-PR, AbortSignal.timeout(this.getRequestTimeoutMS()) at the original pkg/rdd-client/watch.ts used a random 5–10 minute window applied to the entire fetch lifetime; on fire, the previous try/catch turned a timeoutSignal.aborted into done(null) — a graceful close that triggered ListWatch auto-restart. That matched the Kubernetes client-go pattern of forcing periodic reconnects to resume from a fresh resourceVersion.

Post-PR (pkg/rdd-client/watch.ts:64-70,141-143), the timeout is created with setTimeout and cleared in a finally block. Once the body-streaming IIFE launches, the finally clears the timer, so the timeout effectively gates only the headers-arrival window of the initial fetch. There is no longer a client-side periodic reconnect; if the daemon's body socket silently stalls, the read just hangs.

For local IPC this is likely fine, and the error-path reconnect still recovers from drops, but the random 5–10 minute window is now a vestige and obscures the change in semantics. Two options:

  1. Shorten the initial-connect timeout to something HTTP-sized (e.g. 30 s) and rename getRequestTimeoutMS accordingly.
  2. Restore the periodic graceful-close behavior — re-arm the timeout when streaming starts and treat its firing as a normal end-of-stream.

Review Process Notes ¶

Skill improvements ¶

  • Treat <UnionType>[number] indexing as silent widening to string. When a finding alleges that indexing a string-literal union with [number] widens to plain string, verify by mentally substituting a concrete union ('a' | 'b' | 'c') and applying TypeScript's index access rules: literal types treated as char-indexable produce string. Flag this pattern in any callback or generic helper signature where the parameter was previously a precise union and the diff added [number]. Why: this is silent compile-time-safety loss with no runtime symptom, so it survives review unless someone reasons through the type-evaluation.
