## Important Issues

I1. **Steve is never restarted after an unexpected exit — the dashboard silently stays disabled** — `pkg/rancher-desktop/backend/steve.ts:130-140` [Codex GPT 5.5]

```ts
childProcess.on('exit', (code, signal) => {
  if (childProcess !== this.process) { return; } // stale process
  this.#port = 0;
  send('backend/steve-port', 0);
  portLatch.reject(new Error(`Steve process ${ childProcess.pid } exited unexpectedly...`));
});
```

`background.ts:251-260` starts steve only when a `backend/app-status-changed` event reports `KubernetesReady`. After steve is running, an unexpected exit clears the port (`steve.ts:137`) and broadcasts `0` (`steve.ts:138`), but only rejects the already-resolved startup latch — no code schedules a restart. `DashboardOpen.vue:15` gates the button on `port > 0`, so the dashboard stays disabled until Kubernetes status next transitions, which may never happen while the cluster stays ready.

Fix: track a desired-running flag set by `start()`/cleared by `stop()`, and on an unexpected exit (when desired) clear `this.process` and re-`start()` with a small backoff.

I2. **New supply-chain checksum parsers ship without unit tests** — `scripts/lib/dependencies.ts:97,239,298` [Claude Opus 4.8]

```ts
export function parseSha256Checksum(value: unknown): Sha256Checksum   // :97
export async function downloadAndHash(...)                           // :239
export async function fetchUpstreamChecksums(url, algorithm)         // :298
```

These three new functions guard the install-time integrity contract, and their parsing is intricate: GNU (`<hex>  <file>`) versus BSD (`ALG (<file>) = <hex>`) line formats, a hex-width anchor that rejects a wrong-algorithm sidecar, and a basename-alias dedup on collision. The comments document edge cases that no test exercises — `scripts/lib/__tests__/` holds only `build-utils.spec.ts`. A regression in any branch would silently weaken digest verification, and the functions are pure (string in, map out), so they are cheap to test.

Fix: add `scripts/lib/__tests__/dependencies.spec.ts` covering GNU/BSD lines, wrong-algorithm width rejection, basename-collision dedup, and `parseSha256Checksum` accept/reject/normalize cases.

## Suggestions

S1. **Steve teardown is incomplete on the failure and quit paths** — `pkg/rancher-desktop/backend/steve.ts:160-174,235-241` [Gemini 3.1 Pro]

```ts
const port = await portLatch;
await this.waitForReady(port); // :167 — if this throws, the child is left running
this.#port = port;
send('backend/steve-port', port);
return port;
```

Two gaps. (a) When `waitForReady` exhausts its 60 attempts while the process stays alive (`steve.ts:167`), `startInternal` throws but never kills the child, which lingers until the next `start()` restarts it or quit stops it. (b) `stop()` sends `SIGINT` without awaiting exit (`steve.ts:239`) and `background.ts:205-215` quits on the next tick. `kill()` delivers the signal synchronously, so a SIGINT-honoring steve exits cleanly; the residual gap is the missing force-kill fallback if steve ignores it.

Fix: in the failure path, `kill('SIGINT')` the child before rethrowing; make `stop()` await exit and `SIGKILL` after a short timeout.

S2. **`logrus.Fatalf` inside `runSwitch` bypasses the function's error return and deferred cleanup** — `src/go/networking/cmd/host/switch_windows.go:96,102` [Codex GPT 5.5]

```go
vn, err := virtualnetwork.New(&cfg)
if err != nil {
    logrus.Fatalf("creating virtual network failed: %v", err)
}
```

This PR's host-switch refactor inlined the former `run()` into `runSwitch`, which returns errors to a caller that logs and exits and registers `defer cancel()` (`switch_windows.go:84`). The two new `logrus.Fatalf` calls (lines 96, 102) call `os.Exit` directly, skipping that deferred cleanup and the caller's error path; at merge-base both were `return err`. Process exit reclaims resources anyway, so the cost is testability and consistency, not a leak.

Fix: return wrapped errors (`return fmt.Errorf("...: %w", err)`) and let the existing caller handle exit.

S3. **`backend/app-status-changed` types `reason` as `string`, but it can be `undefined`** — `pkg/rancher-desktop/typings/electron-ipc.d.ts:20` [Claude Opus 4.8]

```ts
'backend/app-status-changed': (status: Record<string, readonly [boolean | undefined, string]>) => void;
```

`rdd.ts:167-173` builds each tuple from a Kubernetes condition's `reason`, which is optional, so the second element can be `undefined` while the declared type promises `string`. There is no runtime impact — `background.ts:252` reads only index 0 — but the type misrepresents the payload for any future reader of `reason`.

Fix: widen the tuple to `readonly [boolean | undefined, string | undefined]`, or default `reason` to `''` at the emit site in `rdd.ts`.

## Design Observations

### Concerns

- **Steve has no internal lifecycle owner** `(in-scope)` [Codex GPT 5.5, Gemini 3.1 Pro] — Start and stop hang entirely off the renderer's `KubernetesReady` status event (`background.ts:251-260`) plus `before-quit`. I1 (no restart on exit) and S1 (no kill on readiness failure, no awaited teardown) all stem from this single external driver. A `Steve` manager that owns its own restart-on-crash, kill-on-failure, and awaited teardown would close the whole class at the source instead of patching each path.
- **`download()` codesign cache-hit never repairs `destPath`** `(future)` [Claude Opus 4.8] — On a cache hit, `download()` hashes `${destPath}.unsigned` and returns without confirming `destPath` exists or re-running codesign. The rework correctly hashes pre-signature bytes (fixing the "digest after mutation" hazard), but a future caller that sets `codesign: true` would ship a missing or stale signed binary if `destPath` is deleted while `.unsigned` survives. No current caller sets `codesign`, so it cannot fire today; the latent bug lands with the first consumer.

### Strengths

- **Digest pinning** [Claude Opus 4.8, Codex GPT 5.5] — `dependencies.yaml` records an immutable commit alongside `mobyOpenAPISpec`'s version, and `downloadAndHash` hashes as-downloaded bytes before any mutation; archives cache next to `destPath` and are excluded from packaging.
- **Steve readiness probe** [Gemini 3.1 Pro, Claude Opus 4.8] — `steve.ts` waits on `/v1/namespaces` (404 until the schema controllers register) rather than treating an open port as ready.
- **Host-switch handshake retry** [Claude Opus 4.8] — the `acceptWithTimeout` path closes the listener to unblock `Accept`, drains the channel, and closes the racing connection, handling the goroutine leak cleanly.
- **Reduced main-process surface** [Codex GPT 5.5] — removing the dashboard proxy and its certificate allowlist deletes a class of special cases.

## Review Process Notes

### Skill improvements

- Derive the prompt's Changed Files list from the same merge-base diff that produces the reviewed patch, not from the hosting platform's PR file metadata. When the list comes from the platform's API while the patch is computed locally against the merge-base, the two can diverge — the platform may use a different merge-base or paginate its file set — and any agent that builds its coverage summary from the Changed Files list then silently skips files that appear only in the patch. Generate the list with `git diff <merge-base>..<head> --name-status` so it always matches the diff under review.


```diff
       await this.waitForReady(port);
       this.#port = port;
       send('backend/steve-port', port);
 
       return port;
+    } catch (err) {

+      }
+      throw err;
     } finally {

```

I2. **Synchronous Steve shutdown races with app quit** — `pkg/rancher-desktop/backend/steve.ts:31-33`, `background.ts:204-219` `(important, gap)`

```typescript
    mainEvents.on('before-quit', () => {
      this.stop();
    });
```

The author previously stated "Will fix" regarding the orphaned Steve process on app quit.
