Executive Summary ¶

PR #51 surfaces asynchronous container action failures by adding an icon-error glyph and a tooltip carrying status.lastAction.error to the state badge in the containers table. The wiring matches the daemon's annotation-driven action contract (status.lastAction.state / status.lastAction.error) and reuses the existing BadgeState.icon prop and v-tooltip pattern from Volumes.vue and Images.vue.

Structure: zero critical, one important (gap on the detail page), three suggestions (one correctness gap, one CSS scoping, one stylistic).

The important issue is a feature gap, not a regression: the same badge component (ContainerStatusBadge.vue) is registered as the ContainerInfo.vue page header action via the action prop and is not updated by this PR, so the failure indicator vanishes the moment the user clicks into a container's detail view. The suggestions are minor; one is worth taking together with the I1 fix because the fix lives in the same code path (drive the icon off state === 'Failed' rather than off the optional error string).

Design Observations ¶

Strengths ¶

  • Reads from status.lastAction instead of the patch promise Claude Codex (in-scope) — Action failures arrive asynchronously through the lastAction subresource, so a .catch on the patch request would never see them. The PR honors that contract.
  • Reuses BadgeState's existing icon prop Claude (in-scope) — The badge component already accepts an icon string; the PR uses it directly rather than introducing a parallel widget.
  • Tooltip wiring matches the established { content: undefined } pattern Claude (in-scope) — pkg/rancher-desktop/pages/Volumes.vue:48 and pkg/rancher-desktop/pages/Containers.vue:441-447 already exercise FloatingVue's no-tooltip-when-undefined behavior, so the new caller relies on a code path the page already proves.

Testing Assessment ¶

No unit, component, or e2e test covers the new badge decoration. This matches the rest of pkg/rancher-desktop/pages/ (no Vue page carries a .spec.ts), and the existing containers e2e suite at e2e/containers.e2e.spec.ts:13 is gated with test.describe.fixme. The gap is therefore consistent with surrounding practice rather than a regression introduced by this PR.

Risk-ranked untested scenarios:

  1. Failed with no error — covered by S1; the renderer silently shows nothing.
  2. List/detail parity — covered by I1; only the table reflects the failure.
  3. State transitions — Failed → Succeeded clears the icon (visible by reading the template; no automated assertion).
  4. Stale failure — lastAction persists until the next action overwrites it (per the CRD docstring), so a long-since-failed action keeps the indicator. By design, but worth a Playwright assertion in a follow-up.

Documentation Assessment ¶

No user-facing documentation needs updating. BadgeState.icon, v-tooltip, and the LastAction schema are all documented at their definition sites.

Commit Structure ¶

One commit, one file, one narrowly scoped change. The commit message describes both the trigger (lastAction.state === 'Failed') and the user-visible effect (icon plus tooltip).
