## Suggestions

1. **Goroutine leak in guestagent signal handler** — `src/go/guestagent/main.go:124-128` (suggestion, enhancement) [Gemini 3.1 Pro]

```go
go func() {
    <-sigCh
    log.Debug("Caught interrupt signal, cancelling group context")
    cancel()
}()
```

When `runAgent` returns (through errgroup completion or normal shutdown), this anonymous goroutine blocks indefinitely waiting for a signal. The leak is benign because `runAgent` runs only from `main()` immediately before process exit. However, making the goroutine exit cleanly when the context completes is a low-cost improvement that keeps the function safe for future reuse.

Fix: Use a `select` to exit if the context completes first:

```diff
 go func() {
-    <-sigCh
-    log.Debug("Caught interrupt signal, cancelling group context")
-    cancel()
+    select {
+    case <-sigCh:
+        log.Debug("Caught interrupt signal, cancelling group context")
+        cancel()
+    case <-groupCtx.Done():
+    }
 }()
```

### Suggestions

1. **`wsl.ts` — removed `await` changes execution semantics inside `Promise.all`** — `pkg/rancher-desktop/backend/wsl.ts:1359-1365` (suggestion, regression)

```typescript
// Before (sequential awaits passed to Promise.all — effectively serial):
await this.progressTracker.action('Rancher Desktop guest agent', 50, ...),
await this.execCommand({ root: true }, 'rm', '-f', ...),
await this.execCommand({ root: true }, 'rm', '-f', ...),

// After (promises passed to Promise.all — truly parallel):
this.progressTracker.action('Rancher Desktop guest agent', 50, ...),
this.execCommand({ root: true }, 'rm', '-f', ...),
```

Removing `await` before the items in the `Promise.all` array is actually the correct fix — the old code was a bug where `await` inside a `Promise.all` array expression serializes the calls before `Promise.all` even sees them. The new code properly lets `Promise.all` run them concurrently. The `rm -f` operations and guest agent install are independent, so this is correct. Additionally, the four separate `rm` calls were consolidated into one, reducing overhead. No action needed — just noting the semantic improvement.

2. **`ipcMain.ts` — null coalesce on `JSON.stringify` return** — `pkg/rancher-desktop/main/ipcMain.ts:20` (suggestion, regression)

```typescript
let printableArg = JSON.stringify(arg, removeCircularReferences) ?? 'undefined';
```

`JSON.stringify` returns `undefined` (not `null`) when the input is a bare `undefined`, `Symbol`, or `Function`. The `??` operator catches both `null` and `undefined`, so this works correctly. Minor nit: a comment explaining why the `?? 'undefined'` guard is needed (for `undefined` args in IPC messages) would aid clarity.

3. **`ExtensionManagerImpl.shutdown()` — async→sync change returns `Promise.resolve()`** — `pkg/rancher-desktop/main/extensions/manager.ts:621-641` (suggestion, regression)

```typescript
// Was: async shutdown() { ... await Promise.allSettled(...) }
// Now: shutdown() { ... return Promise.resolve(); }
```

The old code used `Promise.allSettled` to wait for process kills; the new code uses synchronous `for..of` with `.kill()` (which is synchronous and non-blocking) and returns `Promise.resolve()`. This is correct — `.kill()` sends a signal and doesn't need awaiting. The `Promise.resolve()` return preserves the `Promise<void>` contract for callers. Clean simplification.

4. **`k3sHelper.ts` — added `.filter(defined)` to async map** — `pkg/rancher-desktop/backend/k3sHelper.ts:1128` (suggestion, gap)

```typescript
}).filter(defined));
```

The `.map()` callback at line 1108 can return `undefined` when the `if` condition on line 1111 is not met (the implicit `else` returns `undefined`). Adding `.filter(defined)` filters out these `undefined` values before passing to `Promise.all`. This is a correct bug fix for a pre-existing issue.

#### Suggestions

1. **Prevent goroutine leak in signal handler** — `src/go/guestagent/main.go:124-128` (suggestion, enhancement)

```go
	go func() {
		<-sigCh
		log.Debug("Caught interrupt signal, cancelling group context")
		cancel()
	}()
```

When `runAgent` returns (whether through an error propagated out of `errgroup` or by a normal shutdown), the anonymous goroutine blocks indefinitely waiting for a signal, resulting in a goroutine leak. While this is benign in the current execution flow because `runAgent` is only invoked directly by `main()` right before the entire process terminates, it is a good pattern to clean up listener goroutines. Doing so ensures the function remains safe for potential reuse inside long-running contexts in the future.

Fix: Use a `select` statement to exit the goroutine cleanly if the group context completes first.

```diff
 	go func() {
-		<-sigCh
-		log.Debug("Caught interrupt signal, cancelling group context")
-		cancel()
+		select {
+		case <-sigCh:
+			log.Debug("Caught interrupt signal, cancelling group context")
+			cancel()
+		case <-groupCtx.Done():
+		}
 	}()
```
