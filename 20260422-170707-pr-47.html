Executive Summary ¶

This PR replaces the hard-coded rancher-desktop Kubernetes namespace used by the container-engine Vuex module with the App custom resource's spec.namespace. A new plugin in container-engine.ts watches the rdd/kubernetesNamespace getter and re-runs setupResourceWatch when the value changes. A companion commit (441c664fa) corrects every Vuex Plugin<T> annotation from per-module state to RootState, since plugins receive the root store.

The architectural direction is right — the renderer-side store now follows the daemon's API model rather than a frontend constant — and the flattenedGetters mapped type added to ts-helpers.ts is a tidy enhancement that gives rootGetters lookups compile-time safety. The rough edges concentrate around the plugin's startup conditions: the watcher only initializes on a namespace transition, so if App.spec.namespace is implicit (the CRD documents "default" as its default), container-engine never starts; the symmetric rdd module was not given the same re-watch wiring; and setupResourceWatch is now reachable from a new trigger in addition to the pre-existing reconnect path, exposing a concurrency gap. None are blocking, but I1 and I2 are worth a fix before merge.

setupResourceWatch now has three triggers: the namespace watch (container-engine.ts:266, new in this PR), setCurrentNamespace (container-engine.ts:103), and the reconnect path (rddConnection.ts:412-422). It awaits inside the per-resource loop (the registerDisconnectCallback dispatch at 441-448), so two invocations can interleave their close → create → commit → register sequence and leave state._watchers referencing the loser's watcher. The visible symptoms: a ghost watcher with a still-armed 429 retry setTimeout (rddConnection.ts:583-592) running against the old namespace, or _watchersInitialized resolved against a half-replaced watcher set.

The reconnect path already exposed this race, but the namespace-change trigger makes it reachable on every normal startup, not just on backend reconnects.

Fix: serialize invocations with a per-module in-flight promise, mirroring fetchConfigPromise at rddConnection.ts:56-86. Collapse a back-to-back call into the trailing one. As a cheap defense-in-depth, add a #stopped flag to Watcher and short-circuit the 429 retry setTimeout if it fires after close().

Design Observations ¶

Strengths ¶

  • (in-scope) Moving the source of truth from a renderer-local rdd-connection.namespace field to the App resource matches the daemon's API model rather than a hard-coded frontend constant. Codex Claude
  • (in-scope) Strongly typing rootGetters via the new flattenedGetters mapped type gives compile-time safety to cross-module lookups like rootGetters['rdd/kubernetesNamespace'], and lifts UnionToIntersection into utils/typeUtils.ts where the second consumer (ts-helpers.ts) can share it. Gemini Claude
  • (in-scope) Reusing resourceWatchActions() for the namespace-driven reconfiguration keeps the watch lifecycle logic in one place rather than scattering one-off watcher code across each page. Codex
  • (in-scope) The Plugin<RootState> typing fix in commit 441c664fa lands uniformly across all four modules with plugins. Claude

Concerns ¶

Review Process Notes ¶

Skill improvements ¶

  • Treat "watcher shutdown" abort plumbing as runtime-version-dependent, not an automatic critical. When a finding alleges a deliberate-shutdown error leaks through identity comparison (e.g., Object.is(err, sentinel) failing because the runtime wraps the abort reason), trace the abort chain end-to-end before promoting to critical. In modern Node and browsers, AbortController.abort(reason) propagates signal.reason verbatim through fetch and ReadableStreamDefaultReader.read(), so the sentinel survives. Reserve "critical" for cases where the runtime contract demonstrably wraps the reason; otherwise downgrade to a defense-in-depth suggestion.
  • For Vuex/Vue reactive store.watch callbacks, treat "guard against same value" as redundant for primitive sources. Vue's reactive watch fires only when the source value changes. Code that caches the previous value and compares inside the callback (if (newValue === cached) return;) is dead defensive code on a primitive getter. Flag the redundancy as a suggestion, but verify the source is primitive — for object getters, identity-stable references can cause re-fires that the guard would catch.

Repo context updates ¶

  • [repo] rdd/kubernetesNamespace getter is the source of truth for the namespace. When reviewing code that reads or writes Kubernetes namespaces in the renderer, check whether it goes through rdd/kubernetesNamespace (rdd.ts) or hard-codes a string. The pre-PR pattern used rdd-connection.namespace and a hard-coded 'rancher-desktop'; both are gone after PR #47. Stale mappings of either form (e.g., mapTypedState('rdd-connection', { x: 'namespace' })) are dead code that should be removed or repointed at the new getter.
  • [repo] setupResourceWatch is now reachable from three triggers, not one. When reviewing code that calls or modifies setupResourceWatch in pkg/rancher-desktop/store/rddConnection.ts, account for: the namespace-change watch (container-engine plugin), setCurrentNamespace, and the reconnect path inside setupResourceWatch itself. The function does await inside its per-resource loop and is not serialized, so two concurrent invocations can interleave. Flag any code that adds a fourth trigger without addressing serialization.
  • [repo] App spec.namespace is documented as defaulting to "default" server-side, but the TypeScript surface keeps the field optional. When reviewing renderer code that reads app.spec.namespace, treat the value as string | undefined regardless of the CRD documentation — generated client code does not enforce the default. Code that depends on the field being defined needs an explicit fallback.
