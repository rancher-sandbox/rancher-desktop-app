Executive Summary¶

This PR migrates the Images page from the legacy IPC-based image manager to the RDD (Rancher Desktop Daemon) Kubernetes-style API, following the pattern established by the Volumes and Namespaces conversions. It adds image resource definitions and watch infrastructure to the container-engine store, reworks image parsing and display in the component, and wires delete/push actions through the generated RDD client. The PR description acknowledges that "lots of things are expected to be broken" and that image pulling does not yet work.

The review found one clear bug (stale sort column reference), several error-handling gaps, and a handful of dead-code and consistency issues.

Critical Issues¶

1. Stale default-sort-by references a renamed column Claude Codex¶

The header column was renamed from imageName to name (line 218), but default-sort-by still references "imageName". The SortableTable sorting logic looks for a header whose name matches sortBy; no header is named "imageName", so the sort falls through to a default of ['nameSort', 'id']. Because these rows lack a nameSort property, the table sorts by id on initial load instead of by image name.

4. Protected image matching may break with registry-prefixed references Gemini¶

Before this PR, isDeletable checked row.imageName, which was a short name (e.g., moby/buildkit). This PR switches to row.name, which is parsed from repoTag and may include a registry prefix (e.g., docker.io/moby/buildkit). Similarly, rancherImages uses .startsWith('rancher/'), which fails if repoTag includes a registry prefix like docker.io/rancher/k3s. The protectedImages list includes the literal 'moby/buildkit' (line 65), which would not match 'docker.io/moby/buildkit'.

Whether this triggers depends on the reference format the RDD API returns. If Docker Hub images come back without the docker.io/ prefix, the matching works. If they include the prefix, protected images become deletable.

Design Observations¶

Concerns¶

(in-scope) The output window infrastructure (ImagesOutputWindow, startImageManagerOutput, startRunningCommand, imageOutputCuller, Card) remains in the component but is now unreachable: showImageManagerOutput returns keepImageManagerOutputWindowOpen, which is false and never set to true because startImageManagerOutput() is never called. The TODO comments acknowledge that deletion/push output display is not yet implemented. Once output display is wired through the RDD API, this infrastructure may not be the right shape. Claude

(in-scope) The page splits UI preference responsibility: RDD-backed resource state lives in container-engine, while image-page preferences (showAll, namespace) were removed from the old Electron settings IPC but not replaced. The settings data property is pinned to defaultSettings and never updated. Consolidating currentNamespace and showAll into one store-backed source of truth would remove the mismatch. Codex

(future) Namespace switching does not restart the image watcher. watchImages runs once on mount (line 97); onChangeNamespace only commits currentNamespace via setCurrentNamespace. The listContainerNamespacedResource function applies fieldSelector during the initial list (line 20) but the watch stream does not carry the selector. Once supportsNamespaces is enabled, selecting a namespace will not reliably filter images. Codex

Strengths¶

  • The image reference parsing in parsedImages (lines 250–278) is well-documented with ASCII art and handles edge cases (untagged images, registries with ports) cleanly. Claude
  • Moving image mutations into the container-engine store aligns images with the existing RDD resource/watch pattern used for volumes, keeping API calls out of the view layer. Claude Codex

Testing Assessment¶

No tests are added or modified. Given the PR description acknowledges this is WIP, the absence is understandable, but the following scenarios carry the most risk:

  1. Image reference parsing — the regex in parsedImages handles registries with ports, multiple path segments, and untagged images. Unit tests would prevent regressions as the RDD API's reference format stabilizes.
  2. setCurrentNamespace validation — the action throws on nonexistent namespaces; a unit test for the happy path and the error path would be straightforward.
  3. Empty image list — no test covers the zero-images state, so the missing ImagesButtonAdd action went undetected.
  4. imageDelete error handling — the success/failure branching in the store action is testable in isolation.

Documentation Assessment¶

No user-facing documentation changes needed at this stage. The PR is an internal migration of data flow.
