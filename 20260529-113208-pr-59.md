## Important Issues

I1. **`paths.resources` throws on an undefined `resourcesPath`, breaking `paths.spec.ts`** — `pkg/rancher-desktop/utils/paths.ts:142-145` [Codex GPT 5.5]

```ts
get resources() {
  if (electron.app?.isPackaged) {
    return path.join(process.resourcesPath, 'resources');
  }
```

The round-1 I3 fix makes the packaged branch (line 144) call `path.join(process.resourcesPath, 'resources')`. The unit test "should return undefined if resources is missing in production" (`paths.spec.ts:155-157`) sets `isPackaged = true` and `resourcesPath = undefined`, then expects `resources` to be `undefined` at `paths.spec.ts:163`. Accessing the getter now runs `path.join(undefined, …)`, which throws `TypeError: The "path" argument must be of type string`. The CI `test` job is red on exactly this (run 26654913584). The author rewired the test's setup but not the getter's missing-path handling.

Fix: guard the join so the documented "missing in production" contract still holds.

```diff
-    return path.join(process.resourcesPath, 'resources');
+    return process.resourcesPath && path.join(process.resourcesPath, 'resources');
```

I2. **`steve` child process is never stopped on app quit (orphaned process)** — `background.ts:196-215,250-259`; `pkg/rancher-desktop/backend/steve.ts:84` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

```ts
Electron.app.on('before-quit', (event) => {
  if (gone) { mainEvents.emit('quit'); return; }
  // ... no Steve.getInstance().stop()
});
```

Steve is started/stopped only from the `backend/app-status-changed` handler (`background.ts:250-259`), which stops it solely when `KubernetesReady` flips false. The `before-quit` path does not call `stop()`, and the child is spawned without `detached` (`steve.ts:84`), so on macOS/Linux it is not reaped when the Electron parent exits. Quitting (or crashing) while Kubernetes is ready leaks a `steve` holding its port; the next launch spawns a fresh one. Nothing listens on `mainEvents 'quit'` to clean it up.

Fix: stop Steve during shutdown, e.g. `mainEvents.on('quit', () => Steve.getInstance().stop())`, or call it in `before-quit`.

I3. **Dashboard window keeps a stale port after steve stops or restarts** — `pkg/rancher-desktop/window/dashboard.ts:11-29` [Gemini 3.1 Pro]

```ts
if (restoreWindow(window)) {
  return window;
}
const { port } = Steve.getInstance();
```

`openDashboard()` loads `http://127.0.0.1:${port}/…` once at window creation. If steve later stops (K8s `NotReady`) or restarts on a new ephemeral port (K8s flap), nothing reloads or closes the existing window — `restoreWindow` just focuses it. Reopening the dashboard returns the stale window still pointing at the dead port, so the dashboard is broken until the window is manually closed and reopened.

Fix: when the steve port changes (or steve stops), reload the dashboard window's URL or close it so the next open recreates it at the live port.

## Design Observations

### Concerns

- **Steve lifecycle is wired to one signal only** `(in-scope)` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro] — Start/stop hangs entirely off `KubernetesReady` (`background.ts:250-259`). Quit (I2) and dashboard-window staleness (I3) both stem from there being no second owner of the process/window lifecycle. Tying steve teardown to `mainEvents 'quit'` and reacting to port changes in the dashboard window closes both gaps at the source rather than patching each path.
- **Seccomp injection re-derives structure the parser already computed** `(future)` [Codex GPT 5.5] — `injectSeccompOpt`/`seccompInjectionPos` run flat argv scans after `parse()` already separated nerdctl options from container args. Passing the parser's separator index in would remove the whole class of bypass (see Acknowledged Limitations) instead of adding string-matching exceptions. Deferred upstream per the author.

### Strengths

- **Digest-pinned downloads** [Claude Opus 4.8] — `scripts/lib/dependencies.ts`/`download.ts` hash the as-downloaded archive before codesign mutates it, drop the unsigned cache on codesign failure, and pin to immutable release tags.
- **Updater hardening** [Claude Opus 4.8] — `getSha512Sum` rejects non-128-hex bodies before `Buffer.from(…,'hex')` truncates, and `triggerUpdateCheck` rearms after transient errors; both tested.
- **Steve readiness probe** [Claude Opus 4.8, Codex GPT 5.5] — `steve.ts` waits on `/v1/namespaces` (404-until-schemas) rather than treating an open port as ready, and the port flows to the renderer over IPC, decoupling the UI from process management.
- **`paths.resources` realignment** [Codex GPT 5.5] — joining `resources/` in the packaged branch fixes not just steve but the whole class of packaged-asset consumers (icons, `preload.js`, bin paths) that resolved one directory too high; `getRDDPath` joins independently, so there is no double-`resources`. (Completeness gap: the missing-path case, I1.)

## Review Process Notes

### Skill improvements

- When a finding claims a change breaks the build, type-check, or lint, confirm which toolchain step actually processes the cited file type before classifying it. A type error or unused import inside a `.vue`, `.jsx`, or other embedded-script file is build-breaking only if the bundler routes that block through a type-checking loader (e.g. `ts-loader` with `appendTsSuffixTo`, or a separate `vue-tsc`/`fork-ts-checker` step) and the relevant lint rule is enabled under the project's `--max-warnings` gate. Verify the loader `test` patterns and the rule's effective severity; an unverified build-break is a high-severity false positive. Where CI results for the reviewed SHA are available, cross-check a claimed CI-breaking error against the actual job status — a "breaks the build" finding on a SHA whose build job is green is refuted by definition.

### Repo context updates

- [repo] In this repo the production webpack build type-checks only `.ts` files: the `ts-loader` rule in `scripts/lib/build-utils.ts` matches `/\.ts$/` with no `appendTsSuffixTo`, so `.vue` `<script lang="ts">` blocks are compiled by `vue-loader` without type-checking, and there is no separate `vue-tsc` step in CI. Separately, `@typescript-eslint/no-unused-vars` is set to `off` for the whole tree by the `rancher-desktop-compatibility` block in `eslint.config.mts` (despite a `warn` default and `--max-warnings=0`). Do not flag a type error or an unused import inside a `.vue` file as a build or lint blocker; the `package` and `lint` CI jobs will pass regardless. Such issues are at most dead-code suggestions.

### Findings

**Critical Issues**

C1. **Blank page on Container Info navigation** — `pkg/rancher-desktop/pages/containers/ContainerInfo.vue:150` (critical, regression)

```diff
-const activeTab = ref<'tab-logs' | 'tab-shell'>('tab-logs');
+const activeTab = ref<'tab-info' | 'tab-logs' | 'tab-shell'>('tab-info');
```

The PR changes the default `activeTab` to `'tab-info'`, but comments out the `tab-info` `<tab>` component (and its `ContainerInspect` content) in the template. When a user navigates to the container info page, `rd-tabbed` activates the non-existent `'tab-info'`, leaving the page completely blank. The user must deduce to manually click "Logs" to see any content.

Fix: Revert `activeTab` to default to `'tab-logs'` until the info feature is re-enabled, and revert the e2e test that explicitly clicks the "Logs" tab to work around the blank page.

**Important Issues**

I1. **Stale port in dashboard window on Steve restart** — `pkg/rancher-desktop/window/dashboard.ts:9` (important, gap)

```typescript
  if (restoreWindow(window)) {
    return window;
  }
```

If the `steve` process crashes or is restarted when Kubernetes state flaps, it binds to a new ephemeral port. However, `openDashboard()` simply focuses the existing `BrowserWindow` without updating its URL. The dashboard will remain stuck pointing to the dead port.

Fix: Compare the window's current URL port against the active Steve port, and call `window.loadURL(...)` again if the port has changed before returning.

I2. **Orphaned steve child process on exit** — `pkg/rancher-desktop/backend/steve.ts:84`

```typescript
    const childProcess = spawn(stevePath, ['--context', 'rancher-desktop-2'],
      { stdio: ['ignore', 'pipe', 'pipe'], windowsHide: true });
```

The `steve` process is spawned using raw `child_process.spawn` and its lifecycle is not tied to the main application. If Rancher Desktop exits normally without Kubernetes first reaching a `NotReady` state (which triggers the `stop()` listener), or if Rancher Desktop crashes, the `steve` process will be left running in the background as an orphan.

Fix: Register an `app.on('before-quit')` listener to ensure `this.stop()` is called when the application quits, or wrap it in a managed process helper that guarantees teardown.

I3. **seccomp injection bypasses compose containers** — `src/go/nerdctl-stub/seccomp.go:66`

```go
	switch args[i] {
	case runCmd, createCmd:
		return i + 1
```

`seccompInjectionPos` identifies where to inject `--security-opt` by matching the `run` and `create` subcommands. However, `nerdctl compose up` and `nerdctl compose run` handle their container specs directly and are NOT intercepted as individual `run` or `create` commands by the stub. As a result, containers started via compose bypass the Docker default seccomp profile.

Fix: To enforce the profile globally across all containers, including those launched via compose, explore exporting the `NERDCTL_SECCOMP_PROFILE` environment variable (if supported) to the path of `seccomp.json`, or document that compose containers do not receive the strict Docker default profile.

**Suggestions**

S1. **Race condition in fetchInspect** — `pkg/rancher-desktop/components/ContainerInspect.vue:151` (suggestion, enhancement)

```typescript
watch(() => props.containerId, fetchInspect, { immediate: true });
```

`fetchInspect` does not track the latest request. If `containerId` changes rapidly, an older slower request could resolve last, incorrectly updating the `loading` or `error` state for the new container.

Fix: Consider maintaining a `currentRequest` tracking variable to ignore stale responses, or use an `AbortController`.
