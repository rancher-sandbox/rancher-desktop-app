Executive Summary ¶

This PR converts the containers page from the Docker Extension API to the Kubernetes-style RDD API, following the pattern established in #32 for images. Round 1 identified ten issues; the author addressed nine of them in e913b9c4b. Round 2 finds one new critical bug: the logURL computed property returns a new URL object on every store update, causing the log WebSocket watcher to reconnect continuously. Two important issues affect the dormant namespace-switching path, and a few minor issues remain in error handling and sort keys.

Critical Issues ¶

1. Log WebSocket reconnects on every container status update Gemini ¶

The logURL computed (line 87) returns new URL(), which creates a fresh object on every evaluation. The container computed (line 73) depends on the store getter containerById, which re-evaluates whenever the informer pushes any status update. Because Vue's watch at line 191 compares array elements with Object.is(), the new URL reference triggers the watcher even when the URL string has not changed. Each trigger aborts the active WebSocket (lines 197–199), resets the terminal (lines 201–204), and opens a new connection (line 219). The result: log output flickers and reconnects whenever any container's status changes in the background.

pkg/rancher-desktop/components/ContainerLogs.vue
const container = computed(() => {
  return store.getters['container-engine/containerById'](containerId) ?? null;
});

/**
 * Timer used with `waitingForInitialLogs` to reveal the terminal after a delay.
 */
let revealTimeout: ReturnType<typeof setTimeout> | undefined;

const genericLogURL = usePassthroughURL('logs');
const logURL = computed(() => {
  if (!genericLogURL.value || !container.value?.metadata?.name) {
    return undefined;
  }
  return new URL(container.value.metadata.name, genericLogURL.value);
});

// Ref used for triggering reloads when the connection dies.
const reconnectTrigger = ref(0);
let reconnectAttempts = 0;
let reconnectResetTimer: ReturnType<typeof setTimeout> | undefined;
const maxReconnectAttempts = 5;

The watch at line 191 uses Object.is() comparison, so a new URL object triggers reconnect even when the string value is identical.

pkg/rancher-desktop/components/ContainerLogs.vue
// Start streaming logs from the container.
watch([logURL, reconnectTrigger], async([logURL], _, cleanUp) => {
  if (!container.value || !logURL) {
    return;
  }
  errorMessage.value = undefined;
  const streamAborter = new AbortController();
  cleanUp(() => {
    streamAborter.abort();
    clearTimeout(revealTimeout);
  });

Fix: Return a string primitive so Vue compares by value.

-  return new URL(container.value.metadata.name, genericLogURL.value);
+  return new URL(container.value.metadata.name, genericLogURL.value).toString();

Important Issues ¶

1. Namespace refresh dispatches wrong payload shape Codex ¶

The setCurrentNamespace action at line 107 wraps the stored options in { options: ... }, but resourceWatchActions at rddConnection.ts:305 consumes the payload directly as options?: ResourceWatchActionsOptions. The action receives { options: { callback, namespace } } instead of { callback, namespace }, so options?.namespace and options?.callback resolve to undefined at lines 321 and 333. The corrupted payload is then persisted back into _watchers at line 348, breaking all subsequent reconnects.

This bug is dormant because supportsNamespaces() returns false (line 67), so setCurrentNamespace never reaches the dispatch loop. It will break the moment namespace support is enabled.

2. Double reconnect scheduling on socket failure Codex ¶

A failing WebSocket emits both error and close events. Each calls handleStreamError() at line 291 and 303, which schedules a setTimeout at line 323 without guarding against a pending timer. Both timeouts compute the same delay (since reconnectAttempts has not yet incremented), so two reconnect triggers fire in quick succession. The second trigger tears down the connection that the first reconnect just established, wasting one of the five retry attempts.

pkg/rancher-desktop/components/ContainerLogs.vue
    socket.addEventListener('error', (event) => {
      console.error('WebSocket error:', event);
      if (streamAborter.signal.aborted) {
        // Do not set error on intentional aborts.
        return;
      }
      let message = String('message' in event ? event.message : event);

      if (message.startsWith('[object')) {
        message = 'unknown error';
      }
      errorMessage.value = `WebSocket error: ${ message }`;
      handleStreamError();
    });
    socket.addEventListener('close', (event) => {
      console.log('WebSocket closed:', event);
      if (streamAborter.signal.aborted) {
        // Do not set error on intentional aborts.
        return;
      }
      if (!event.wasClean || event.code !== 1000) { // 1000 = normal closure
        errorMessage.value = `WebSocket closed unexpectedly: ${ event.reason || 'code ' + event.code }`;
      }
      if (!event.wasClean) {
        handleStreamError();
      }
    });
  } catch (err: any) {
    console.error('Error setting up log stream:', err);
    errorMessage.value = `Failed to load logs: ${ err.message || err }`;
  }
});

function handleStreamError() {
  if (!isRunning) {
    // If the container isn't running, we expect the log stream to fail, so
    // don't show a reconnect button in this case.
    return;
  }
  // On unexpected log streaming error, retry with exponential backoff by
  // touching the `reconnectTrigger` ref, which is a dependency of the log
  // streaming watcher.
  if (reconnectAttempts < maxReconnectAttempts) {
    const delay = Math.pow(2, reconnectAttempts) * 1_000;
    setTimeout(() => {
      reconnectAttempts++;
      // Trigger a reconnect.
      reconnectTrigger.value++;
    }, delay);
  }
}

Fix: Store the reconnect timer and clear it before scheduling.

+let reconnectTimer: ReturnType<typeof setTimeout> | undefined;
+
 function handleStreamError() {
   if (!isRunning) { return; }
   if (reconnectAttempts < maxReconnectAttempts) {
     const delay = Math.pow(2, reconnectAttempts) * 1_000;
-    setTimeout(() => {
+    clearTimeout(reconnectTimer);
+    reconnectTimer = setTimeout(() => {
       reconnectAttempts++;
       reconnectTrigger.value++;
     }, delay);
   }

Design Observations ¶

Concerns ¶

1. (in-scope) Watcher replay in setCurrentNamespace reconstructs payloads by hand Codex ¶

The watcher replay in setCurrentNamespace (container-engine.ts:105–108) reconstructs watch* dispatch payloads by hand, even though rddConnection.ts:348 already stores the canonical options. Moving the replay loop into a shared helper inside rddConnection.ts would eliminate the shape-mismatch bug (Important #1) as a category and ensure future store modules get namespace switching for free.

Strengths ¶

  • The containerById getter at container-engine.ts:73 centralizes the container lookup that three components previously duplicated, directly addressing the round 1 design observation. ClaudeCodex
  • The AbortController-based lifecycle in ContainerLogs.vue provides clean separation between the terminal, WebSocket, and Vue lifecycles. The onCleanup integration with Vue's watch ensures connections terminate when dependencies change. ClaudeGemini
  • The usePassthroughURL composable cleanly encapsulates the multi-step URL resolution (config → configmap → controller → passthrough endpoint) with proper reactivity. Claude

Testing Assessment ¶

No new tests accompany these changes. The __xtermTerminal e2e hook was restored per round 1 feedback, but the e2e tests remain disabled. Untested scenarios ranked by risk:

  1. Log WebSocket lifecycle — Mount, receive data, status update does not reconnect, actual disconnect triggers reconnect, unmount cleans up. Would catch Critical #1.
  2. Container start/stop round-trip — The spec.state field was just fixed; a test would catch future regressions.
  3. Namespace switching with active watchers — setCurrentNamespace re-dispatches all watchers. Would catch Important #1.
  4. Socket failure producing both error and close events — Would catch Suggestion #2 (double reconnect).
