Executive Summary ¶

This PR migrates the Images page from the old IPC-based data flow to the new RDD API watch/informer pattern, consistent with the volumes and namespaces migration already in the codebase. The structural approach is sound and follows established patterns well. Two actionable issues emerged: a regex that misparses image references containing registry ports without explicit tags, and inconsistent error handling between imagePush/imageScan and the imageDelete action. Several known-incomplete areas (push output, scan output, settings persistence, namespace switching) are documented with TODOs and acknowledged by the author as intentional for this incremental migration.

The greedy (.*) matches up to the last colon, so an image reference like localhost:5000/myimage (port-based registry, no explicit tag) parses as name='localhost', tag='5000/myimage'. 3. Simplify shortHash regex Gemini (suggestion, enhancement) ¶

This dynamically compiles a RegExp on every call. A static regex or string operations would be simpler and avoid repeated compilation.

pkg/rancher-desktop/components/Images.vue
    shortHash(sha: string) {
      const length = 6;
      const [, prefix, actualHash] = new RegExp(`^([^:]+:)(.{${ length * 2 },})$`).exec(sha) ?? [];

      if (!prefix) {
        return undefined;
      }

      return `${ prefix }${ actualHash.slice(0, length) }..${ actualHash.slice(-length) }`;
    },

Design Observations ¶

Concerns

  • Namespace watcher lifecycle not connected to namespace state (in-scope) Codex Gemini: setCurrentNamespace (container-engine.ts:77-84) commits SET_CURRENT_NAMESPACE but does not restart watchImages. The fieldSelector filtering only applies during the initial listFn call inside the Watcher (rddConnection.ts:315-325); subsequent watch events can include images from all namespaces. This is currently inert because supportsNamespaces (container-engine.ts:60) is hardcoded false and the namespace dropdown is hidden. When namespace support is enabled, the watcher must restart (or the component must filter client-side) on namespace change. The TODOs at pages/Images.vue:83 and :111 acknowledge this gap.
  • Split UI state between Electron settings and the RDD store (in-scope) Codex: The migration moves image data into container-engine, but the page no longer subscribes to settings-read/settings-write. onShowAllImagesChanged (pages/Images.vue:110-112) only logs to console, and the selected namespace is not persisted. The author has acknowledged this in review comments and documented it with TODOs. Consolidating all Images-page state into the store with one initialization path from persisted settings would remove this dual-source gap.

Strengths

  • The migration follows the established defineResource/resourceState/resourceWatchActions pattern consistently with volumes and namespaces, making the new images resource feel native to the architecture. Claude Codex Gemini
  • Image reference parsing in parsedImages (components/Images.vue:249-277) is well-documented with an ASCII art diagram and clear fallback logic for untagged images. Claude
  • The mapTypedMutations improvement in entry/store.ts:117-121 properly handles mutations with no payload parameter, fixing a genuine type safety gap. Claude Gemini
  • Using Intl.NumberFormat with unit: 'byte' and notation: 'compact' (components/Images.vue:205-210) leverages platform locale-aware formatting instead of hand-rolling a size formatter. Claude

Testing Assessment ¶

No unit tests exist for components/Images.vue or pages/Images.vue, and none are added. Given the regex-based image reference parsing, unit tests for edge cases would be valuable:

  1. References with ports but no tag: localhost:5000/myimage (highest risk — see Finding #1)
  2. References with ports and tags: registry.test:5000/image:latest
  3. References with no explicit registry: library/alpine:3.18
  4. Untagged images (empty repoTag)
  5. Multi-level repositories: ghcr.io/org/sub/image:v1
  6. Namespace switching updates the displayed image list (once namespace support is enabled)
