Executive Summary ¶

This PR moves container log rendering from text to binary WebSocket frames in step with rancher-desktop-daemon#323, regenerates the RDD client, adds a settled getter on the rdd store for the backend progress bar, and reorders generate-rdd-client.ts so it starts the RDD service itself (and uses RDD as its docker backend). The binary log refactor is small, localized, and correct. The regenerated client, however, drops the spec.state field on Container and documents that actions now travel via the AnnotationAction metadata annotation — but containerSetState, which is still the handler for the Start/Stop buttons on the containers page, was not updated. The generator-script restructuring is mostly an improvement (proper service stop in finally, docker work inside the RDD-alive window), but a few smaller regressions snuck in: the client tree is now deleted before startup/fetch is proven, the header comment lost its Docker prerequisite, and set running=true is not followed by a readiness probe.

Design Observations ¶

Concerns ¶

  • Regenerated-client and call-site drift is unmanaged (in-scope) Claude Codex. The rdd-client: regenerate commit looks mechanical, but it carries a server-API contract change that has direct call-site consequences (I1). Two mitigations would help: the regenerate-commit body could call out added/removed/required-changed fields, and at the type level, weakening spec to any swallows what should be a compile error — a typed helper in @rdd-client or container-engine for "request container action" would localize the contract and turn the next schema change into one compile-time break instead of N runtime regressions.

Strengths ¶

  • Binary message refactor is small and localized (in-scope) Claude Codex Gemini. One type flip on buffer, one binaryType = 'arraybuffer', one type guard, and two new Uint8Array(chunk) writes. The surrounding control flow (reset on abort, flush on terminal mount, reconnect backoff) is unchanged, so the diff is easy to verify end-to-end.
  • Generator now tears down RDD on failure (in-scope) Claude. Moving the docker build/run inside try { … } finally { rdd service stop } means an early failure in codegen no longer leaves the daemon running.

Testing Assessment ¶

No automated tests were added or updated. Risk-ranked gaps:

  1. Container Start/Stop (highest) — nothing covers containerSetState, so I1 surfaces only when a developer manually clicks Start/Stop. A Playwright check that asserts a running container transitions to stopped (or the inverse) would prevent recurrence.

Repo context updates ¶

UPDATE — rdd-client patch contract is two layers of indirection. The existing deep-review-context.md entry warns that getPreferredMediaType picks application/json-patch+json over the setHeaderOptions(MergePatch) override. This review shows there is a second trap: patchNamespaced* bodies now also care about what to patch — the Container CRD has moved action requests from spec.state to the AnnotationAction metadata annotation, with outcomes reported via status.lastAction. When reviewing any caller of patchNamespacedContainer (or sibling patch* APIs on generated models where spec is typed any), verify both the Content-Type negotiation and that the patch body still matches the current CRD contract. An any-typed spec field is a loud signal that the server no longer accepts desired-state on that resource.
