## Executive Summary

This PR migrates the containers page and log viewer from the Docker Extension API (`window.ddClient`) to the Kubernetes-style RDD API, following the pattern established by the images conversion in PR #32. The change introduces a `usePassthroughURL` composable for WebSocket-based log streaming, restructures `ContainerLogs.vue` around watch-based lifecycle management with `AbortController`, and adds Vuex actions for container state transitions and deletion. Two critical regressions block the merge: the Start/Stop action patches a nonexistent `spec.desiredState` field (the API defines `spec.state`), and the log-streaming WebSocket URL inherits `https:` from the kubeconfig server URL instead of converting to `wss:`. Five important issues also need attention before merge.

2. **WebSocket log URL uses `https:` instead of `wss:`** — `components/ContainerLogs.vue:88,201` [Gemini 3.1 Pro] (critical, regression)

```ts
// passthrough.ts:58 — inherits protocol from kubeconfig server URL

// ContainerLogs.vue:201 — passed directly to WebSocket constructor

The `logURL` computed at `ContainerLogs.vue:88` appends the container name but preserves the protocol. Fix: Convert the protocol in the `logURL` computed:
```diff

+ const url = new URL(container.value.metadata.name, genericLogURL.value);

5. **`RootGetters` type evaluates to `any` for all modules** — `entry/store.ts:45-47` [Claude Opus 4.6] (suggestion, regression)

```ts
export type RootGetters = {
  [K in keyof Modules]: Modules[K] extends { getters: any } ? ReturnType<Modules[K]['getters']> : never;
};
```

Module getters are plain objects, not functions. `ReturnType<ObjectType>` evaluates to `any`, so every entry in `RootGetters` collapses to `any`. The type compiles without error but provides no type safety for `rootGetters` in `GetterTree` at `ts-helpers.ts:65`.

## Design Observations

**Concerns**

1. **(in-scope)** Each component independently resolves the current container from the store array using `find(c => c.metadata?.name === id)` — `ContainerInfo.vue:143`, `ContainerLogs.vue:75`, and `ContainerStatusBadge.vue:28` (broken). A shared computed or selector for "current container by route ID" would eliminate the store-shape mismatch that caused the badge regression and reduce the surface area for similar bugs. [Codex GPT 5.4]

**Strengths**

1. The watch-based lifecycle in `ContainerLogs.vue` with `AbortController` and `onCleanup` is a substantial improvement over the old imperative `initializeTerminal`/`startStreaming`/`stopStreaming` pattern. Each watch handler owns its cleanup, eliminating an entire class of stale-state bugs. [Claude Opus 4.6]

2. The `usePassthroughURL` composable cleanly encapsulates controller-manager discovery logic and is reusable for any passthrough endpoint. The computed chain from config map → info → controller → URL is well-structured. [Claude Opus 4.6]

3. The container actions (`containerSetState`, `containerDelete`) follow the established pattern from `imageDelete`/`imagePush` in the same store file, maintaining consistency across the migration. [Claude Opus 4.6, Codex GPT 5.4]
