Executive Summary ¶

This PR migrates the containers page and log viewer from the Docker Extension API (window.ddClient) to the Kubernetes-style RDD API, following the pattern established by the images conversion in PR #32. The change introduces a usePassthroughURL composable for WebSocket-based log streaming, restructures ContainerLogs.vue around watch-based lifecycle management with AbortController, and adds Vuex actions for container state transitions and deletion. Two critical regressions block the merge: the Start/Stop action patches a nonexistent spec.desiredState field (the API defines spec.state), and the log-streaming WebSocket URL inherits https: from the kubeconfig server URL instead of converting to wss:. Five important issues also need attention before merge.

5. RootGetters type evaluates to any for all modules Claude (suggestion, regression) ¶

Module getters are plain objects, not functions. ReturnType<ObjectType> evaluates to any, so every entry in RootGetters collapses to any. The type compiles without error but provides no type safety for rootGetters in GetterTree at ts-helpers.ts:65.

pkg/rancher-desktop/entry/store.ts
export type RootGetters = {
  [K in keyof Modules]: Modules[K] extends { getters: any } ? ReturnType<Modules[K]['getters']> : never;
};

Fix:

export type RootGetters = {
  [K in keyof Modules]: Modules[K] extends { getters: infer G }
    ? { [P in keyof G]: G[P] extends (...args: any) => infer R ? R : never }
    : never;
};

Design Observations ¶

Concerns

  • Duplicated container-lookup logic (in-scope) Codex: Each component independently resolves the current container from the store array using find(c => c.metadata?.name === id) — ContainerInfo.vue:143, ContainerLogs.vue:75, and ContainerStatusBadge.vue:28 (broken). A shared computed or selector for "current container by route ID" would eliminate the store-shape mismatch that caused the badge regression and reduce the surface area for similar bugs.

Strengths

  • The watch-based lifecycle in ContainerLogs.vue with AbortController and onCleanup is a substantial improvement over the old imperative initializeTerminal/startStreaming/stopStreaming pattern. Each watch handler owns its cleanup, eliminating an entire class of stale-state bugs. Claude
  • The usePassthroughURL composable cleanly encapsulates controller-manager discovery logic and is reusable for any passthrough endpoint. The computed chain from config map → info → controller → URL is well-structured. Claude
  • The container actions (containerSetState, containerDelete) follow the established pattern from imageDelete/imagePush in the same store file, maintaining consistency across the migration. Claude Codex

Testing Assessment ¶

  1. Start/Stop actions untested — no store-level or UI test verifies that Start/Stop sends the correct patch body. This would have caught Critical #1.
  2. E2e container log scrolling broken — the __xtermTerminal hook removal (Important #5) breaks e2e/pages/container-logs-page.ts scroll helpers at lines 52, 60, 68.
  3. Container details badge untested — no test opens /containers/info/:id and asserts the ContainerStatusBadge renders the current container's state.
  4. Table sorting untested after row-shape change — no test verifies that clicking column headers sorts correctly with the new RDD field structure.
  5. Existing container e2e suite disabled — e2e/containers.e2e.spec.ts is currently disabled (line 9), so none of these regressions would be caught pre-merge.
  6. usePassthroughURL composable untested — the non-trivial logic (JSON parsing with fallback, controller priority, URL construction) would benefit from unit tests covering edge cases such as missing config map data.

Documentation Assessment ¶

The spelling dictionary update (passthroughs) is appropriate. No other user-facing documentation changes are needed.

Acknowledged Limitations ¶

  1. "// TODO: Determine if the backend supports namespaces." — store/container-engine.ts:65. supportsNamespaces() always returns false, hiding the namespace dropdown and disabling namespace-specific filtering. The migration makes this limitation more visible because namespace selection is now wired through the currentNamespace getter, which always returns undefined.
  2. The PR description explicitly states "many things are expected to be broken" — this is an incremental step in a larger migration where backend passthrough endpoints may not yet be fully implemented.
