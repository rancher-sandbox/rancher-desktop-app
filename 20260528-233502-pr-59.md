## Executive Summary

This large upstream merge moves the dashboard onto an embedded steve server (resolves #27) and folds in many upstream fixes. Several merge artifacts ship broken: the container Info tab (now the default tab) throws on open against store API that no longer exists; `scripts/dependencies/global.ts` imports modules that were never split out, failing CI lint and `yarn rddepman`; the new steve binary resolves to the wrong packaged path; and the new seccomp injection is bypassable by valid flag orderings.

All three reviewers independently flagged the Info-tab crash. Codex caught the packaged-path and electron-manifest issues; Gemini alone caught the seccomp bypass; Claude alone caught the download-overwrite regression and the extension-URL hardening gap. One Gemini finding (dashboard.ts unhandled rejection) was a false positive against code that does not exist in the file.

## Critical Issues

C1. **Container Info tab throws against nonexistent store API** — `pkg/rancher-desktop/components/ContainerInspect.vue:258,267,280` [Claude Opus 4.8, Codex GPT 5.5, Gemini 3.1 Pro]

```ts
import type { ContainerInspectData } from '@pkg/store/container-engine';     // 258
const data = computed<ContainerInspectData | undefined>(
  () => store.state['container-engine'].inspectData[props.containerId]);     // 267
await store.dispatch('container-engine/fetchContainerInspect', { ... });     // 280
```

The merge rewrote `container-engine.ts` to the RDD resource-watch pattern (state at `store/container-engine.ts:53`), but the upstream docker-inspect surface never came with it: `inspectData`, `fetchContainerInspect`, and `ContainerInspectData` exist only in `ContainerInspect.vue`. At runtime `store.state['container-engine'].inspectData` is `undefined`, so `inspectData[props.containerId]` throws `TypeError` in the `data` computed (line 267). `ContainerInfo.vue:154` defaults `activeTab` to `'tab-info'` and `ContainerInfo.vue:103` renders `<container-inspect>` for that tab, so every container detail view crashes on open. No `vue-tsc` typecheck and a `fixme`'d e2e suite let it through.

Fix: port the inspect path into `container-engine.ts` (add `inspectData` state, a `fetchContainerInspect` action over the RDD/container API, and export `ContainerInspectData`), or drop the Info tab until the store backing exists.

## Important Issues

I1. **`global.ts` imports modules and classes that do not exist** — `scripts/dependencies/global.ts:9-38` [Claude Opus 4.8, Codex GPT 5.5]

```ts
import { AlpineLimaISO, Lima, Qemu, SocketVMNet } from '@/scripts/dependencies/lima';
import { MobyOpenAPISpec } from '@/scripts/dependencies/moby-openapi';
import { Moproxy, WSLDistro } from '@/scripts/dependencies/wsl';
...
new tools.KuberlrAndKubectl(), new tools.Helm(), new tools.DockerCLI(), // and 10 more
```

`scripts/dependencies/` has no `lima.ts`, `moby-openapi.ts`, or `wsl.ts`, and `tools.ts` exports only `GoLangCILint`, `CheckSpelling`, and `Steve` — not the 13 `tools.*` classes referenced at lines 14-38. The file is new in this PR and `rddepman.ts:10` imports `globalDependencies`. `tsconfig.json` includes `**/*`, so `yarn lint:nofix` (run by `test.yaml`) fails the TypeScript check, and the scheduled `rddepman.yaml` job fails at module load. The shipped app is unaffected — `postinstall.ts` references only existing classes. Codex rated this critical (CI blocker); Claude rated it important (tooling, not product runtime).

Fix: reduce `globalDependencies` to the dependencies this fork manages (`GoLangCILint`, `CheckSpelling`, `Steve`, `Wix`, `Electron`, plus extensions) and delete the dead imports. Add a smoke test that imports `rddepman.ts`.

I2. **`downloadTarGZ`/`downloadZip` overwrite the destination unconditionally** — `scripts/lib/download.ts:223-241,283-290` [Claude Opus 4.8]

```ts
// copyFile overwrites destPath unconditionally, so a postinstall run while
// Rancher Desktop or another shell holds the binary fails with EBUSY/EPERM
// on Windows or ETXTBSY on Linux.
await fs.promises.copyFile(path.join(workDir, fileToExtract), destPath);
```

At the merge-base, both functions returned early when `destPath` existed (default `overwrite=false`), never touching a held binary. The refactor dropped that guard and now re-extracts and copies onto `destPath` on every postinstall. The comment predicts the exact failure (EBUSY/EPERM on Windows, ETXTBSY on Linux), so it is acknowledged — but the change makes a previously-absent failure happen on every run, which promotes it past the acknowledgment gate. The refactor does fix a real bug (stale binary after a version bump), so reverting wholesale is wrong.

Fix: skip the extract/copy when `destPath` exists and `download()` was a cache hit (archive unchanged); re-extract only when the archive was re-fetched. This needs `download()` to signal whether it re-downloaded.

I3. **Packaged steve binary resolves one directory above where it is bundled** — `pkg/rancher-desktop/backend/steve.ts:83` [Codex GPT 5.5]

```ts
const stevePath = path.join(paths.resources, os.platform(), 'internal', osSpecificName);
```

`electron-builder.yml:11` packages the local `resources/` directory via `extraResources: - resources/`, landing files at `<resourcesPath>/resources/…`. But `paths.resources` (`utils/paths.ts:143-144`) returns bare `process.resourcesPath` when packaged, while `getRDDPath` in the same file (`paths.ts:66`) joins `process.resourcesPath, 'resources', …`. The new steve consumer therefore looks in `<resourcesPath>/<platform>/internal/steve` rather than `<resourcesPath>/resources/<platform>/internal/steve`, so a packaged build cannot start the dashboard — the headline feature. The `getRDDPath` special-case is the tell that the shared getter is inconsistent; the same getter also feeds tray icons, `preload.js`, and bin paths, so verify the fix against a real packaged build before changing the getter.

Fix: align `paths.resources` with `getRDDPath` (join `'resources'` when packaged) and audit the other consumers, or join `'resources'` locally in `steve.ts`. Update `paths.spec.ts` to assert the packaged suffix.

I4. **Seccomp injection is bypassable by valid flag orderings** — `src/go/nerdctl-stub/seccomp.go:49-73` [Gemini 3.1 Pro]

```go
for i < len(args) && strings.HasPrefix(args[i], "-") { /* skip globals */ }
switch args[i] {
case runCmd, createCmd:        return i + 1
case containerCmd:
    if i+1 < len(args) && (args[i+1] == runCmd || args[i+1] == createCmd) { return i + 2 }
}
return -1
```

`seccompInjectionPos` re-scans args with a simplified loop instead of reusing the structure `parse()` built. A global flag between `container` and `run` defeats it: `nerdctl container --namespace default run alpine` reconstructs (via `parse_args.go:254`) to `["container","--namespace","default","run",…]`, and the `containerCmd` branch requires `run` immediately after `container`, returns `-1`, and skips injection. Bunched short flags taking a value (`-dn value`) fail the same way. The Docker seccomp profile then silently does not apply, weakening the CVE mitigation. Common forms work, and the user can disable seccomp anyway, so this is important, not critical. New in this PR and untested — `seccomp_test.go` has no interspersed-flag case.

Fix: derive the injection point from the parsed command structure rather than re-scanning, or handle flags between `container` and the subcommand plus bunched short options. Add test cases for both orderings.

## Suggestions

S1. **ContainerInspect ignores namespace changes and masks fetch errors** — `pkg/rancher-desktop/components/ContainerInspect.vue:291` [Claude Opus 4.8]

```ts
watch(() => props.containerId, fetchInspect, { immediate: true });
```

The watcher keys only on `props.containerId`, but `fetchInspect` also reads `props.namespace`; a namespace change with the same id will not refetch. Separately, `data` is a store-backed computed, so a failed refetch sets `error.value` while the template still renders the previous container's data (the error branch shows only when `data` is falsy), hiding the failure. This matters once C1 is fixed.

Fix: `watch([() => props.containerId, () => props.namespace], fetchInspect, { immediate: true })`, and scope `data` to the current id so a failed fetch surfaces the error.

S2. **Extension-supplied URL goes into an `href` without scheme validation** — `pkg/rancher-desktop/pages/extensions/installed.vue:117-127,222` [Claude Opus 4.8]

```ts
extensionLink(ext: ExtensionMetadataSource): string {

Installed extensions are semi-trusted, so the risk is low.

S3. **Electron manifest version lags `package.json`** — `pkg/rancher-desktop/assets/dependencies.yaml:23` [Codex GPT 5.5]

## Review Process Notes

### Skill improvements

- When a security control (seccomp, AppArmor, capability drop, a forced `--security-opt`) is enforced by injecting a flag or argument into a command line, verify the injection point is computed from the tool's canonical parse result, not a separate simplified re-scan. A re-scan that diverges from the real parser creates silent bypasses: enumerate the invocation forms the underlying tool accepts — global flags interspersed at any position, bunched short options that take a value, subcommand aliases — and confirm the injection still fires for each. Flag any control-injecting code that re-implements argument parsing instead of reusing the parsed structure, because the bypass fails open and is invisible to the user.
