Executive Summary ¶

This PR migrates the containers page from the Docker Extension API to the RDD Kubernetes-style API. The author addressed round 1 and 2 findings: the spec.desiredState → spec.state fix, containerById getter, sort key corrections, and RootGetters type mapping are all correctly implemented. Two important issues remain: the patch request's Content-Type/body format mismatch will likely cause the RDD API to reject start/stop operations, and the container grouping reads labels from a different source than the kube-system filter, which will break project grouping.

None.

Important Issues ¶

1. Patch Content-Type sends JSON Patch header with merge-patch body Gemini (important, regression) ¶

The generated client's patchNamespacedContainer method lists three accepted Content-Types: application/json-patch+json, application/merge-patch+json, and application/apply-patch+yaml. The getPreferredMediaType helper selects the first "JSON-like" match — application/json-patch+json. That format requires an array of RFC 6902 operations, but the body { spec: { state } } is a merge-patch object. A server that validates Content-Type against body structure will reject every start/stop request.

The kube-system filter at line 218 reads io.kubernetes.pod.namespace from status.labels (container runtime labels), while the project grouping at lines 240–243 reads the same label keys from metadata.labels (Kubernetes resource metadata). If the RDD backend does not copy container runtime labels to metadata.labels, grouping never matches on pod name or namespace, and all containers fall into "Standalone Containers." 2. Stopped containers never begin streaming after they start Codex (suggestion, gap) ¶

The log-stream watcher at line 191 depends only on logURL and reconnectTrigger. If the user opens logs for a stopped container, the WebSocket fails and handleStreamError (line 314) suppresses the retry because isRunning is false. When that container later starts, neither logURL (based on container name, not state) nor reconnectTrigger changes, so the watcher never fires. The user must navigate away and back to see logs.

let reconnectTimer: ReturnType<typeof setTimeout> | undefined;

function handleStreamError() {
  clearTimeout(reconnectTimer);
  if (!isRunning) {
    // If the container isn't running, we expect the log stream to fail, so
    // don't show a reconnect button in this case.
    return;
  }
  // On unexpected log streaming error, retry with exponential backoff by
  // touching the `reconnectTrigger` ref, which is a dependency of the log
  // streaming watcher.
  if (reconnectAttempts < maxReconnectAttempts) {
    const delay = Math.pow(2, reconnectAttempts) * 1_000;
    reconnectTimer = setTimeout(() => {
      reconnectAttempts++;
      // Trigger a reconnect.
      reconnectTrigger.value++;
    }, delay);
  }
}

Fix: Add isRunning (or the container's status) as a watch dependency and trigger a reconnect when it transitions to running.

Design Observations ¶

Concerns ¶

(in-scope) Coupling the terminal lifecycle to DOM presence via v-if/v-else in ContainerLogs.vue causes reconnects to destroy the terminal. Treating the loading indicator as an overlay instead of a mutually exclusive branch would decouple transport state from DOM state and eliminate this class of bugs. Codex

Strengths ¶

  1. The containerById getter centralizes container lookup and is used consistently across ContainerStatusBadge, ContainerLogs, and ContainerInfo — a meaningful improvement over the prior per-component array searches. Claude Codex
  2. The usePassthroughURL composable cleanly encapsulates ConfigMap discovery and URL construction, keeping ContainerLogs focused on display logic. Claude
  3. Storing watcher options alongside the watcher itself in rddConnection.ts:213,348 enables the setCurrentNamespace action to re-dispatch watchers with their original options — a pragmatic infrastructure addition. Claude
  4. The RootGetters type and Intersect<Values<...>> pattern in typings/store.d.ts elegantly types Vuex's flattened getters map without hardcoding module names. Gemini
