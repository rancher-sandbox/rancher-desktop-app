## Important Issues

1. **Regex parser mishandles image references with ports but no explicit tag** — `pkg/rancher-desktop/components/Images.vue:261` [Gemini 3.1 Pro] (important, regression)

```ts
const [, name, tag] = /^(.*):([^:]*)$/.exec(reference) ?? ['', reference || image.status.id, untaggedTag];
```

The greedy `(.*)` matches up to the *last* colon, so an image reference like `localhost:5000/myimage` (port-based registry, no explicit tag) parses as `name='localhost'`, `tag='5000/myimage'`. This breaks the downstream registry extraction at line 263, the `isPushable` check (which requires a `/` in `name`), and the `isDeletable` protected-image matching. The second commit fixed the analogous regex in `pages/Images.vue` (changing `/:.*?$/` to `/:[^/]*?$/`), but this regex in `components/Images.vue` was not updated to match.

Confirmed as a regression via `git blame`: line 261 was introduced in commit `dfbeebb57`.

Fix: Ensure the tag capture group excludes slashes, consistent with the fix already applied in `pages/Images.vue`:

```diff
-        const [, name, tag] = /^(.*):([^:]*)$/.exec(reference) ?? ['', reference || image.status.id, untaggedTag];
+        const [, name, tag] = /^(.*):([^/:]*)$/.exec(reference) ?? ['', reference || image.status.id, untaggedTag];
```

2. **`imagePush` and `imageScan` lack error handling, inconsistent with `imageDelete`** — `pkg/rancher-desktop/store/container-engine.ts:86-129` [Claude Opus 4.6] (important, gap)

```ts
imagePush(
  { rootState },
  { image }: { image: RDDClient.IoRancherdesktopContainersV1alpha1Image },
) {
  const config: RDDClient.KubeConfig = rootState['rdd-connection'].config;
  const client = config.makeApiClient(RDDClient.ContainersRancherdesktopIoV1alpha1Api);
  return client.createNamespacedImagePushRequest({ /* ... */ });
},
```

`imageDelete` (lines 130-153) wraps its API call in `try/catch` and commits failures to `state.error` via `SET_ERROR`. Neither `imagePush` (lines 86-107) nor `imageScan` (lines 108-129) has equivalent error handling — they return the raw promise. Additionally, `doPush` in `components/Images.vue:430-432` does not `await` the result, so any failure produces an unhandled promise rejection. This is distinct from the "display push output" TODO: even with output display, a missing `try/catch` means the action silently rejects rather than reporting through state.

Fix: Add `async`/`try`/`catch` matching the `imageDelete` pattern:

```diff
-  imagePush(
+  async imagePush(
     { rootState },
     { image }: {
       image: RDDClient.IoRancherdesktopContainersV1alpha1Image,
     },
   ) {
     const config: RDDClient.KubeConfig = rootState['rdd-connection'].config;
     const client = config.makeApiClient(RDDClient.ContainersRancherdesktopIoV1alpha1Api);

-    return client.createNamespacedImagePushRequest({
+    try {
+      return await client.createNamespacedImagePushRequest({
         namespace: image.metadata!.namespace!,
         // ...
       });
+    } catch (error: any) {
+      commit('SET_ERROR', { error, source: 'images' });
+    }
   },
```

Same pattern for `imageScan`.


### Gemini 3.1 Pro

### Executive Summary
This change migrates the image management UI to the new Rancher Desktop Daemon (RDD) API. The core UI components, state operations, and API bindings have been successfully updated; however, there are critical regressions regarding namespace filtering where switching namespaces fails to restart the background watchers, leading to cross-namespace state pollution. Additionally, a flawed regex parser breaks the UI and actions for images with ports but no explicit tags.

### Findings

#### Critical Issues

1. **Namespace changes do not update the displayed images and cause state pollution** — `pkg/rancher-desktop/store/container-engine.ts:77-85`, `pkg/rancher-desktop/pages/Images.vue:112-114`
(critical, regression)

When a user selects a different namespace in the UI, `setCurrentNamespace` updates `state.currentNamespace`, but it does not restart the image or volume watchers. Because the `fieldSelector` (which filters by `status.namespace`) is only evaluated during the initial `listFn` call inside the `Watcher` (`rddConnection.ts`), the application continues polling the old namespace. Furthermore, the underlying Kubernetes `Watch` stream receives events for images across *all* containerd namespaces. Over time, images from other unselected namespaces will silently pollute the Vuex state and appear in the UI. Additionally, `currentNamespace` is never initialized, causing the initial load to inappropriately pull and display all namespaces.

Fix: Dispatch the watch actions again when the namespace changes, and strictly filter the state within the Vue component to guard against un-filtered watch events.

```typescript
// pkg/rancher-desktop/store/container-engine.ts
  async setCurrentNamespace({ commit, state, dispatch }, { namespace }: { namespace: string | undefined }) {
    if (namespace !== undefined && !state.namespaces?.some(ns => ns.metadata?.name === namespace)) {
      const error = new Error(`Cannot set current namespace to nonexistent namespace ${ namespace }`);
      commit('SET_ERROR', { error, source: 'namespaces' });
      console.log(error);
    } else {
      commit('SET_CURRENT_NAMESPACE', namespace);
      // Restart watchers to apply the new fieldSelector
      await dispatch('watchImages');
      await dispatch('watchVolumes');
    }
  },
```

*Note: You should also add a frontend filter in `pages/Images.vue` (e.g. `this.images.filter(img => img.status?.namespace === this.currentNamespace)`) before passing it to the table, to protect against parallel namespace event streaming.*

#### Important Issues

2. **Regex parser mishandles image references with ports** — `pkg/rancher-desktop/components/Images.vue:235`
(important, regression)

```typescript
const [, name, tag] = /^(.*):([^:]*)$/.exec(reference) ?? ['', reference || image.status.id, untaggedTag];
```

This regex assumes the last colon always separates the tag. If an image has no explicit tag but its registry includes a port (e.g., `localhost:5000/myimage`), the regex incorrectly matches `5000/myimage` as the `tag` and `localhost` as the `name`.
This breaks the UI display and causes `isPushable(row)` to incorrectly return `false` because the parsed `name` (`localhost`) does not contain a slash. It also breaks the `isDeletable(row)` check for protected system images, potentially allowing users to delete protected images if they contain ports. The similar regex used in `pages/Images.vue` avoids this by ensuring the tag portion contains no slashes.

Fix: Use a regex that ensures slashes are not present in the tag portion, or fall back safely.

```diff
-        const [, name, tag] = /^(.*):([^:]*)$/.exec(reference) ?? ['', reference || image.status.id, untaggedTag];
+        const match = reference.match(/^(.*):([^/:]*)$/);
+        const name = match ? match[1] : (reference || image.status.id);
+        const tag = match ? match[2] : untaggedTag;
```

#### Suggestions

3. **Simplify `shortHash` regex generation** — `pkg/rancher-desktop/components/Images.vue:464-471`
(suggestion, enhancement)

```typescript
    shortHash(sha: string) {
      const length = 6;
      const [, prefix, actualHash] = new RegExp(`^([^:]+:)(.{${ length * 2 },})$`).exec(sha) ?? [];
```

The `shortHash` function dynamically compiles a new `RegExp` for every image row on every render cycle. This is computationally expensive and unnecessarily complex for splitting a string by its colon prefix. 

Fix: Use basic string operations to separate the algorithm from the dynamic allocation of regex objects.

```typescript
    shortHash(sha: string) {
      const parts = sha.split(':');
      if (parts.length < 2) return undefined;
      
      const prefix = parts[0] + ':';
      const actualHash = parts.slice(1).join(':');
      
      if (actualHash.length < 12) return undefined;

      return `${ prefix }${ actualHash.slice(0, 6) }..${ actualHash.slice(-6) }`;
    },
```

### Design Observations

**Concerns**
- **ListWatch and State Pollution** `(in-scope)`: The architectural pattern of mapping API `watch` events directly into Vuex state without re-verifying that the incoming events match the currently selected `fieldSelector` guarantees state pollution. The underlying `@kubernetes/client-node` cache blindly appends all events. This structural design requires applying strict client-side filtering on all computed getters before passing Vuex collections to the views.

**Strengths**
- The Vuex typings in `pkg/rancher-desktop/entry/store.ts` (`mapTypedMutations`) have been effectively improved to infer conditional payloads natively, preventing runtime dispatch errors and removing overly loose `any` types.

### Testing Assessment
1. **Namespace switching:** There are no tests to verify that changing the selected namespace accurately updates the underlying table rows or resets the data context.
2. **Registry port permutations:** The image parsing logic lacks unit tests validating varying image reference configurations (e.g., `host:port/image:tag`, `host:port/image`, `host/image:tag`, `image`).

### Documentation Assessment
No specific documentation gaps were found, though user-facing documentation may need updating once pulling and pushing behavior is fully wired to the backend API.
