Executive Summary ¶

The PR renames the application to Rancher Desktop 2, switches the Windows app id to io.rancherdesktop.app2, gives the MSI a fresh UpgradeCode, parameterises the WiX template ($(var.appName), $(var.appId)), and rewires the icon flow to a real icon.ico. Build plumbing is reworked so the runtime productName flows from package.json into the electron-builder config, the macOS/Windows signing configs, and the WiX -d definitions. Renderer pages and the default layout now read productName from package.json to render the title.

What's missing is the long tail of consumers that still hard-code Rancher Desktop / Rancher Desktop.exe / Rancher Desktop.app. rdctl's app-path lookup, the e2e suite, the smoke-test installer, scripts/install-latest-ci.sh, and scripts/populate-update-server.ts all break the moment the rename ships. The WiX file keeps the old AppGUID, so RD2 still triggers the legacy NSIS uninstall and shares HKCU/HKLM PATH-marker keys with RD1 — the "side-by-side" goal stated in the issue is not yet achievable. A handful of UI strings (the KubernetesError version line, app.update) still say "Rancher Desktop" in the same surfaces where the title now says "Rancher Desktop 2."

The build-script work is in good shape; the renderer touch-ups are correct as far as they go; the gaps are downstream consumers, not the files in the diff.

Design Observations ¶

Concerns ¶

  • Multiple sources of truth for the product name (in-scope) Claude. The rename touches package.json (productName), electron-builder.yml (overridden in code), build/signing-config-win.yaml (regex-rewritten), build/signing-config-mac.yaml (regex-rewritten), build/wix/main.wxs (parametrised via $(var.appName)), and installer-win32-gen.tsx (computed key in JSX). Three different mechanisms (override, rewrite, parametrise) for the same conceptual value. The next renamer (RD3?) needs to remember which files self-update and which do not. A single "branding bundle" emitted at build time and consumed by every downstream file would shrink this surface. Closely related to I1 (rdctl Go side has yet another copy).
  • Source-tree mutation during packaging (in-scope) Gemini. scripts/package.ts::createWindowsResources writes the generated icon to resources/icons/icon.ico directly inside the working tree. The .gitignore addition keeps it out of git status, but writing under resources/ is an anti-pattern for a packaging script. Writing the icon to dist/ (or workDir) and referencing it via extraResources in electron-builder.yml would keep the build idempotent and the source tree pristine.

Strengths ¶

  • Mac .app bundle lookup is now rebrand-proof (in-scope) Claude. scripts/lib/sign-macos.ts:48-53 switched from a literal Rancher Desktop.app to a directory listing of *.app. The same pattern (glob with sanity check) would fix I4's smoke-test issue.
  • WiX is correctly parameterised (in-scope) Claude Gemini. $(var.appName) and $(var.appId) replacing literal strings in main.wxs and installer-win32-gen.tsx is exactly the right pattern for a parametric installer. The remaining hard-codes are the AppGUID and firewall display names (I2).

  • Side-by-side install primitives are in place (in-scope) Gemini. Rotating the appId to io.rancherdesktop.app2 and the WiX UpgradeCode to a fresh GUID gives RD2 its own MSI identity. Once I2 (AppGUID) is resolved, the foundation for parallel install is sound.

Review Process Notes ¶

Repo context updates ¶

  • ADD: productName is set in package.json, not electron-builder.yml. The packaging script (scripts/package.ts) overrides the YAML value at build time with _.set(config, 'productName', buildUtils.packageMeta.productName) before electron-builder runs. When reviewing branding or rename changes, treat package.json:productName as the source of truth and trace consumers from there. The YAML value is dead code.
  • ADD: Side-by-side install identity is split across three GUIDs in WiX. The MSI's <Product UpgradeCode> controls major-upgrade behaviour (different UpgradeCode = different product). The <WixVariable Id="AppGUID"> controls (a) NSIS-uninstall registry search and (b) HKCU/HKLM SOFTWARE\<AppGUID>\EnvironmentVariablesSet PATH-marker keys. Each component's Guid is its own value. When reviewing a rename or rebrand intended to coexist with the previous product, verify all three are rotated, not just the UpgradeCode.
  • ADD: rdctl Go side has its own copy of the product name. src/go/rdctl/pkg/paths/paths_{windows,darwin}.go and src/go/rdctl/pkg/factoryreset/factory_reset_windows.go hard-code Rancher Desktop / Rancher Desktop.exe. There is no build-time injection from package.json into the Go binaries today. Any branding change that touches package.json:productName must be paired with a Go-side update (or a build-time ldflags -X constant) for rdctl start, rdctl shutdown, autostart, and factory-reset to work against the renamed app.
