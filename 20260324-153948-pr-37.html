The application.theme setting is defined in settings.ts:53–57 for the enum, line 88 for the default, validated (settingsValidator.ts:100), exposed in the Preferences UI (ApplicationBehavior.vue:90–113), and documented in command-api.yaml.

export enum Theme {

  DARK = 'dark',

The default value at line 88:

    autoStart:              false,

Suggestions¶

1. Goroutine leak in guestagent signal handler Gemini¶

When runAgent returns (through errgroup completion or normal shutdown), this anonymous goroutine blocks indefinitely waiting for a signal. The leak is benign because runAgent runs only from main() immediately before process exit. However, making the goroutine exit cleanly when the context completes is a low-cost improvement that keeps the function safe for future reuse.

src/go/guestagent/main.go
	groupCtx, cancel := context.WithCancel(context.Background())
	defer cancel()
	group, ctx := errgroup.WithContext(groupCtx)

	sigCh := make(chan os.Signal, 1)
	signal.Notify(sigCh, syscall.SIGTERM)

	go func() {
		s := <-sigCh
		log.Debugf("received [%s] signal", s)
		cancel()
	}()

	var portTracker tracker.Tracker

Fix:

Use a select to exit if the context completes first:

 go func() {
-    <-sigCh
-    log.Debug("Caught interrupt signal, cancelling group context")
-    cancel()
+    select {
+    case <-sigCh:
+        log.Debug("Caught interrupt signal, cancelling group context")
+        cancel()
+    case <-groupCtx.Done():
+    }
 }()

Design Observations¶

Concerns¶

  1. Container shell should be capability-driven, not renderer-driven (in-scope) Codex
    The shell tab renders unconditionally. If the backend advertised containerExec support and the UI gated the tab on that capability, partial reverts like 27187db76 could not leave dead features behind. A capability-check pattern (e.g., an IPC query or feature registry) would eliminate this category of frontend/backend desynchronization.

Strengths¶

  • ContainerInfo.vue rendering strategy Claude: The v-show vs v-if distinction (lines 10–14) preserves terminal DOM/PTY state across tab switches while recreating logs fresh.
  • Structured concurrency in Go Gemini: The errgroup usage across switch_windows.go and guestagent/main.go provides clean teardown when any component fails.
  • IPC listener cleanup Claude Gemini: ContainerShell.vue calls removeListener before on to prevent duplicate handlers across reconnects.
  • rdctl config tests Claude Codex: Thorough coverage in config_test.go — valid config, missing files, invalid JSON, CLI overrides, defaults, and validation.
  • yarn-dedupe automation Claude: Clean script with safe defaults (no-push) and idempotent PR creation.

Testing Assessment¶

  1. No runtime coverage for theme application: The added validator tests (settingsValidator.spec.ts:439–461) verify enum acceptance, but no test confirms the preference actually changes the UI appearance.
  2. Shell feature has no active test coverage: Commit 27187db76 deleted containerExec.spec.ts, and the new e2e tests in e2e/containers.e2e.spec.ts:302 are marked fixme.
  3. Interactive runClient() mode untested: The new interactive stdio mode in mobyClient.ts and nerdctlClient.ts has no tests. The mock at mock.ts:308 adds the overload signature but returns a stub that does not match WritableReadableProcess.

Documentation Assessment¶

  • command-api.yaml documents the new application.theme enum.
  • Translation strings for the theme UI exist in en-us.yaml.
  • Spelling dictionary updated with GOWORK and toolsets.
  • No changelog or README updates needed for an internal merge PR.
  • The theme preference and shell tab should not appear in release notes until they function.

Commit Structure¶

Commit 27187db76 (“Remove containerExec”) deletes the backend handler but leaves the upstream Shell tab renderer, page object, e2e tests, and interactive runClient() support intact. This partial revert creates Finding 1. A cleaner approach would be either a pure upstream merge (keeping the feature as-is) or a merge plus a full revert of all shell UI/client pieces. For this merge PR’s purpose (pulling in the postinstall fix), the partial state is acceptable with an acknowledged TODO.

Acknowledged Limitations¶

  1. Container exec reimplementation pending — Commit 27187db76 message: “This will need to be eventually reimplemented in RDD instead.” The deletion is intentional; the Shell tab frontend is orphaned until RDD support lands.
  2. Container Shell tests disabled — e2e/containers.e2e.spec.ts:304: test.describe.fixme('Container Shell Tab'). The fixme marker documents that these tests are known-broken, consistent with the missing backend.
